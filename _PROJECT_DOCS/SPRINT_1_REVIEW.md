### Security Fixes (commit `4fd1e9e`)
Three security issues from AUDIT.md §6 were addressed in `server.js` only:

- **`POST /api/auth/reset-password` disabled (🔴 risk #1).** The route previously reset any account's password given only an email address — a direct account-takeover vector. It now returns 501 with a clear message. No email infrastructure exists to support a proper token flow; disabling is the correct interim fix.
- **`POST /api/parse` gated with `requireAuth` + model locked (🔴 risk #2).** This was an open, unauthenticated relay to the Anthropic API that forwarded arbitrary `model`, `messages`, and `system` from the request body. It is now auth-gated and the model is fixed server-side via `const ALLOWED_MODEL = 'claude-sonnet-4-20250514'`. Callers can no longer select the model.
- **`POST /api/parse-note` gated with `requireAuth` (🔴 risk #2).** The NLP note-parsing endpoint was also unauthenticated. Single-line fix; no behavioral change for authenticated users.

**What this means:**
- New business logic lives in pure, testable service modules — not in `server.js`.
- `server.js` remains the integration point (routes call services; services don't touch the DB).
- `App.jsx` grows only by component imports; new UI is in isolated components.
- The pattern is incremental decomposition, not refactoring. The monoliths are not smaller — but they are no longer the only destination for new logic.

## 3. Risks That Remain

### 🟠 Medium — SESSION_SECRET insecure default
`server.js` line 27: `secret: process.env.SESSION_SECRET || 'cliniq-secret-change-me'`

If `SESSION_SECRET` is not set in the deployment environment, session cookies are signed with a known, public string — making them forgeable. For a prototype running locally this is acceptable. For any shared or externally accessible deployment it is not. The fix is one line: `process.exit(1)` when the env var is missing in production.

### 🟠 Medium — Login silently auto-registers
`POST /api/auth/login` creates a new account for any unknown email. This was a Replit convenience and is not a security hole per se (no data is exposed), but it means there is no real gate on account creation. A typo in an email creates a permanent orphaned account. No fix was applied in Sprint 1 because changing login behavior requires a product decision (is open self-registration intentional?).

### 🟡 Low — Dead Replit scaffolding still tracked
`main.py`, `pyproject.toml`, `replit.md`, and `.replit` are still committed to git. They are inert (nothing imports or runs them), but they add confusion and bulk. Safe to delete in a single cleanup commit.

### 🟡 Low — Unused dependencies
`cors` and `concurrently` are in `package.json` but neither is imported or used. Dead weight. Safe to remove.

### 🟡 Low — `/api/parse-note` uses its own inline model string
The model ID is hardcoded inline in `/api/parse-note`, while `/api/parse` now uses the `ALLOWED_MODEL` constant. Both strings are identical today, but if the model is updated, `/api/parse-note` could be missed. Should reference `ALLOWED_MODEL`.

### 🟡 Low — `App.jsx` and `server.js` remain large monoliths
`App.jsx` is ~4,424 lines; `server.js` is ~1,070 lines. No decomposition of existing code was attempted (correctly — this was out of Sprint 1 scope). The modular service pattern introduced in Sprint 1 is the right direction; the monoliths should be decomposed incrementally over subsequent sprints.

### 🟡 Low — No integration tests; no auth layer tests
The 20 unit tests cover only the pure service functions. The auth routes, the patient CRUD routes, and the new `/api/v2` routes have no automated test coverage. End-to-end testing was not possible in this session because the server requires `DATABASE_URL` and `ANTHROPIC_API_KEY` to boot.

## 6. Is Sprint 1 Production-Safe for This Prototype?

**Yes, with one condition.**

Sprint 1 is a significant net improvement over `main` in every dimension:
- The two 🔴 account-takeover and open-relay risks are closed.
- The repo is now properly structured (gitignore, wired tests, no stale build artifacts).
- All new code is deterministic, tested, and isolated from the existing monolith.
- No existing behavior was broken or changed.

**The condition:** Before sharing the app with anyone beyond the developer (e.g., demo to NYU faculty, user testing), `SESSION_SECRET` must be set as an environment variable. The current fallback (`'cliniq-secret-change-me'`) is public and makes session cookies forgeable. This is a configuration step, not a code change — set it in the deployment environment.

The silent auto-register behavior is a known quirk of the Replit-era architecture. For a capstone demo with a controlled set of users it is low risk. It should be noted in any demo briefing.
